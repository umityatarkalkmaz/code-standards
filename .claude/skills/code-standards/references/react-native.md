# React Native / Expo Standards

Verified: 2026-09-26

This file adds mobile-specific rules on top of [javascript.md](javascript.md). TypeScript
strict mode, naming, ESLint flat config and general JS security rules from javascript.md
still apply; this file overrides it only where stated.

> **Version rule**: install every Expo/React Native package with `npx expo install <pkg>`, never
> `npm install <pkg>@latest`. The Expo SDK pins compatible native versions; npm `latest` is
> often ahead of the SDK (e.g. React Native 0.87 vs SDK 57's 0.86). `npx expo install --check`
> reports drift.

## Tooling

- Default to Expo (managed workflow with Continuous Native Generation). Use bare React Native
  only when a native requirement cannot be met by Expo modules or a config plugin; say why.
- Create projects with `npx create-expo-app@latest`; dependencies stay project-local.
- `tsconfig.json` extends Expo's base and adds the strict flags from javascript.md:

```json
{
  "extends": "expo/tsconfig.base",
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitOverride": true,
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["**/*.ts", "**/*.tsx", ".expo/types/**/*.ts", "expo-env.d.ts"]
}
```

- ESLint: `npx expo lint` sets up `eslint-config-expo`. Keep the config as ESM in
  `eslint.config.mjs` (the Expo package is CommonJS without `exports`, so import the file path):

```js
import { defineConfig } from "eslint/config";
import expoConfig from "eslint-config-expo/flat.js";

export default defineConfig(expoConfig, {
  ignores: ["dist/", ".expo/", "android/", "ios/"],
});
```

- **Module format**: all app source uses ESM syntax (`import`/`export`). Do not add
  `"type": "module"` to an Expo app's `package.json`; leave Expo-generated tooling configs
  (`metro.config.js`, `babel.config.js`) in the form Expo creates them.
- Prettier as in javascript.md.
- Builds and releases through EAS (`eas build`, `eas submit`, `eas update`); `eas.json` is
  committed. Install EAS CLI as a dev dependency or run it with `npx eas-cli`.
- Commands: `npx expo start`, `npx expo lint`, `npx tsc --noEmit`, `npx jest`,
  `npx expo install --check`, `npx expo-doctor`.

## Project Layout

```text
app/                    # Expo Router routes (file-based)
  _layout.tsx           # root layout (providers, navigation container)
  (tabs)/               # route group, no URL segment
  [id].tsx              # dynamic route
src/
  components/           # shared UI
  features/<feature>/   # feature modules: screens' logic, hooks, api
  lib/                  # platform-agnostic utilities, api client
  constants/
assets/                 # images, fonts
app.config.ts           # dynamic app config (reads env); app.json if static
eas.json
tsconfig.json
eslint.config.mjs
```

- Routes live only in `app/`; keep route files thin and import from `src/`.
- `android/` and `ios/` are generated by `npx expo prebuild` (CNG) and gitignored per project
  when using CNG; commit them only in bare projects.
- Platform-specific code via file suffixes (`Button.ios.tsx`, `Button.android.tsx`) or
  `Platform.select`, not scattered `Platform.OS` checks.

## Naming

- Follow javascript.md: `camelCase` functions and variables, `PascalCase` components and types.
- Component files `PascalCase.tsx`; Expo Router route files keep router conventions
  (`_layout.tsx`, `index.tsx`, `[id].tsx`, `+not-found.tsx`).
- Hooks start with `use` and are Action-Object where they perform work: `useFetchUser`.
- Styles: `StyleSheet.create` objects named by role (`styles.container`), not by appearance.

## Security Specifics

- **The app binary is public.** Anything bundled can be extracted: JS bundle, `app.config`
  `extra`, and every `EXPO_PUBLIC_*` variable (inlined at build time). Never put API secrets,
  private keys or service-role tokens in the app; keep them on a backend.
- Build-time secrets (signing, private registry tokens) live in EAS environment variables
  with secret visibility, never in `eas.json` or the repo.
- **Token storage**: `expo-secure-store` (Keychain / Keystore) for auth tokens and credentials.
  Never AsyncStorage, MMKV without encryption, or plain files for secrets.
- **Deep links**: treat every incoming URL and Expo Router param as untrusted input; validate
  with a schema before use. Never perform state-changing actions from a link without user
  confirmation and auth.
- **Network**: HTTPS only. Keep Android cleartext traffic disabled and iOS ATS enabled; do not
  add ATS exceptions or `usesCleartextTraffic` without a stated reason.
- **WebView**: avoid it for untrusted content. If used, set an `originWhitelist`, disable
  `javaScriptEnabled` unless required, and validate every `onMessage` payload.
- **Logs**: no tokens or personal data in `console.*`; strip debug logging in release builds.
- **Permissions**: request only what a feature needs, at the moment it is needed, with a
  user-facing purpose string (in the target user language).
- **OTA updates**: `eas update` channels per environment; never ship an update that changes
  native code expectations of an older runtime version (`runtimeVersion` policy set).

## Testing

- `jest-expo` preset with `@testing-library/react-native`; test files `*.test.tsx` next to
  the component or under `__tests__/`.
- Test behavior through the rendered UI (`screen.getByRole`), not implementation details.
- Test names describe behavior in English: `it("shows an error for an invalid email", ...)`.
- End-to-end with Maestro or Detox when the project needs it.

## Checklist

- [ ] Packages installed with `npx expo install`; `npx expo install --check` and
      `npx expo-doctor` report no problems.
- [ ] `npx tsc --noEmit` passes with the strict flags.
- [ ] `npx expo lint` and `npx prettier --check .` pass.
- [ ] `npx jest` passes.
- [ ] No secrets in the bundle, `app.config`, or `EXPO_PUBLIC_*`; tokens in `expo-secure-store`.
- [ ] Deep link params and route params schema-validated.
- [ ] No cleartext HTTP, no unjustified permissions, no sensitive data in logs.
- [ ] New env vars documented in `.env.example` (public vs. build-secret noted).
